  2274→2. **`mail/route.ts` (line 90) + `mail/mailboxes/route.ts` (line 35)** — Passwords "encrypted" with `Buffer.from(password).toString("base64")`. Schema comment literally says `// stored (mock-encrypted)`. Base64 is encoding, not encryption — any DB read leaks plaintext passwords. **Fix**: Use `crypto.createCipheriv('aes-256-gcm', ...)` with a key derived from `process.env.MAIL_ENCRYPTION_KEY`, store iv+tag alongside the ciphertext.
  2275→3. **`oauth/connect/[platform]/route.ts` (lines 108, 119)** — PKCE `code_verifier` generated with `Math.random().toString(36)…` 4 times concatenated. Twitter branch also sets `code_challenge_method: "plain"` (line 110), further weakening the protection. **Fix**: Use `crypto.randomBytes(32).toString('base64url')` for the verifier and `crypto.createHash('sha256').update(verifier).digest('base64url')` for the S256 challenge.
  2276→4. **`oauth/callback/[platform]/route.ts` (line 235)** — `code_verifier: state.cv ?? "challenge"`. When `state.cv` is missing (e.g. for non-Twitter flows that mistakenly hit this branch), it sends the literal string `"challenge"` as the PKCE verifier, which will always fail token exchange. Silent breakage. **Fix**: If `state.cv` is missing for a PKCE platform, redirect with an error.
  2277→5. **`api-keys/route.ts` (line 8)** — API keys generated with `Math.random()` (40-char `sf_…` keys). API keys are bearer tokens used for authentication. **Fix**: `crypto.randomBytes(32).toString('base64url')`.
